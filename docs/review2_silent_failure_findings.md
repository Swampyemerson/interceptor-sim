**field_score.py reports the CPA as the minimum over a coarse resample grid — at PX4's default 5 Hz position logging a true 0.30 m KILL scores 2.02 m MISS**  
`scripts/field_score.py:443-449, 483-486, 606, 859-861; self-test pins dt at 723 and 805` · _correctness_
- **Claim:** score_engagement() takes CPA = min(range) over a uniform grid whose step is the FINER log's median sample interval clamped to <=0.2 s (field_score.py:443-449, 483-486). Quantization error is ~v_rel*dt/2, i.e. 1-2 m at a 20 m/s closing speed — 2-4x the 0.5 m lethal radius — so the KILL/MISS verdict is decided by log rate, not by geometry. PX4's default logger records vehicle_global_position (the source field_score PREFERS, field_score.py:212-218) at a 200 ms interval = 5 Hz: ~/PX4-Autopilot/src/modules/logger/logged_topics.cpp:142 `add_topic("vehicle_global_position", 200)`. - **Failure mode:** One-shot field day. Interceptor rams the target at a true 0.30 m CPA at ~20 m/s closing. field_score.py is handed the two real logs with no --dt (04_pull_logs.sh:158-160 never passes one) and prints `verdict: MISS, CPA 2.022 m`, writes it to the JSON, and draws it on the plot. **A detection dropout makes the yaw command chase itself: 108 deg of uncommanded yaw in 2 s, guaranteeing the target is never re-acquired**  
`flight/deploy/seeker_loop.py:240,299,328-329; contrast scripts/m4_intercept.py:3760-3777` · _silent-failure_
- **Claim:** seeker_loop.py:328-329 recomputes `yaw_deg = psi_deg(NOW) + degrees(self._last_bearing_rad)` every tick, including ticks with no detection, where `_last_bearing_rad` is the STALE last-seen camera bearing. As the vehicle yaws toward the command, psi grows and the command grows with it — a pure positive-feedback integrator that spins the aircraft at a constant rate for the whole dropout. Simultaneously lambda_hat coasts on its rate-capped rate and v_perp integrates a_cmd to the ±8 m/s clamp. m4_intercept.py does NOT do this: on a no-detection tick it holds last_cmd (m4_intercept.py:3768) or commands yaw = psi (:3775).
- **Failure mode:** Any dropout of ~0.5 s or more (endgame FoV loss is documented as EXPECTED) rotates the body-fixed camera off the target and pins the lateral command at its clamp. The loss becomes self-sustaining. Under real_flight the spin is bounded at 2 s / ~108 deg by FAILSAFE 5; run standalone (the documented on-vehicle command, flight/deploy/README.md:116-121) seeker_loop has no lost-target failsafe at all, so the spin is unbounded.
- **Decision:** Do NOT adopt m4's hold-last-command verbatim (measured worse: beta +30.00 vs -9.25 deg on a 30 deg/s crossing LOS after 1 s dark). Instead, four small, testable changes:

1. LATCH THE ABSOLUTE YAW, COAST IT ON THE ESTIMATED LOS RATE (flight/deploy/seeker_loop.py:327-329). On a detection tick store `self._yaw_cmd_deg = psi_deg + degrees(bearing_h)`; on a no-detection tick do NOT recompute from live psi — advance the stored value by the FROZEN estimate: `self._yaw_cmd_deg += degrees(lambda_dot) * dt`. This kills the transient runaway (the advance rate becomes the ESTIMATED LOS rate, not the un-slewed pointing error) while KEEPING the accidental benefit measured in the crossing case, and it matches the constant-LOS-rate doctrine already built and tested in flight/terminal_coast.py (flight/tests/test_terminal_coast.py:76-98) — which seeker_loop currently does not use at all.

2. MAKE STALENESS VISIBLE AND GATE ON IT. Add `meas_age_s = t - self.lam._last_correction_t` to StepTelemetry, stop integrating v_perp once age > ~2 detector periods (measured: +1.8 m/s of lateral velocity accumulated on a stale rate in 0.5 s), and set a `stale: bool` flag on the tick. Today nothing in the setpoint or the telemetry distinguishes a live command from one running open-loop on a 2 s old bearing.

3. BOUND THE STANDALONE PATH. Either give seeker_loop.run_mavsdk a lost-target abort, or delete the standalone on-vehicle invocation at flight/deploy/README.md:116-121 and point it at real_flight.py (the actual on-vehicle entry point per ADR-0081). Same README block still shows `--weights drone_finetuned_quad_v2.onnx` (line 119) and the config table still lists it as the default (line 129) — stale since c3bd0d9 changed the code default to n-mono; that is the already-fixed blind-model defect surviving in the doc.

4. REGRESSION TEST (the thing that would have caught it): N detections then M dark ticks; assert `abs(yaw_cmd(t) - yaw_cmd(t_last_det)) <= abs(degrees(lambda_dot)) * (t - t_last_det) + eps`. And re-time FAILSAFE 5: with a 20 deg residual bearing and a 45 deg/s yaw loop, the target leaves a +-49.85 deg FoV at 1.55 s, so `engage_lost_target_s = 2.0` (real_flight.py:250) can never fire in time to preserve re-acquisition — either shorten it or make the fix in (1) the thing that keeps the target in frame.
